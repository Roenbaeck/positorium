# Positorium 0.3.0-beta.5

Save a business rule in Positorium with `add constraint` and run it when
the evidence is ready with `check constraint`. For example, a maintainer
can check for undated orders after both the order and date feeds have arrived.
Each check returns the policy revision, its verdict, and the evidence behind
its findings. [Traqula constraint reference](https://github.com/Roenbaeck/positorium/blob/v0.3.0-beta.5/docs/reference/TRAQULA.md#saved-constraints)

## Saving and revising a rule

- The policy is a Thing in the `Constraint` class. Its name and Traqula
  source use the shared roles `name` and `source`. The first successful save
  creates the class if needed.
- Saving the same name again appends a source posit to the same policy.
  Its appearance time comes from `at` or the script's `@NOW`. Retrying the
  same source at the same appearance time returns the existing revision.
- A named check selects the uniquely latest applicable revision at its
  cutoff. Use `as of` for a historical cutoff or pass the store-qualified
  revision to run that exact code again. Tied or incomparable latest
  revisions produce an ambiguity diagnostic with the candidate identities.

## Checking the evidence

A check reads one snapshot and reports `satisfied`, `violated`, or
`indeterminate`. The maintainer can declare a load complete using a delivery
manifest. A missing order date can then establish a violation. While the feed
is incomplete, the same missing date leaves the result indeterminate. Each
finding identifies its subject and can cite witness posits. An explicit audit
can preserve the report in the store. [Constraint design and examples](https://github.com/Roenbaeck/positorium/blob/v0.3.0-beta.5/docs/design/CONSTRAINTS.md)

Traqula now tests interval overlap, containment and disjointness, shifts dates
by calendar days, and computes the minimum and maximum days between dates of
different precisions. The cancellation example uses country-specific deadlines
and checks for a recorded approval when customer service exercises its
discretion. [Worked cancellation constraint](https://github.com/Roenbaeck/positorium/blob/v0.3.0-beta.5/traqula/cancellation-constraint.traqula)

## Compatibility and installation

Format 1.0 stores open directly. Traqula stays at version 1 and the saved
definition and finding report have their own version 1 contract. Rust callers
that match `ExecutionParameter` exhaustively must add arms for `Thing` and
`Posit`. This source change accounts for the minor version increment.
[Contract versions](https://github.com/Roenbaeck/positorium/blob/v0.3.0-beta.5/docs/reference/CONTRACTS.md)

Install the Python beta with

```sh
python -m pip install --upgrade 'positorium==0.3.0b5'
```
