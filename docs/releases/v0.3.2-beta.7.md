# Positorium 0.3.2-beta.7

This Rust crate release includes the embedded register fixes from issue #6.
To upgrade an application that uses an on-disk store, run

```sh
cargo add positorium@=0.3.2-beta.7 --no-default-features --features persistence
```

The query planner uses literal-value postings and can start a join from a
store-qualified identity in a condition such as `where ?s = $session`.
Both searches and mutations accept Thing and Posit parameters directly in
appearances, for example `($s, session)`.

Constraint report version 2 returns `snapshot.digest`, `snapshot.count`, and
`read_posits` by default. If your code reads `snapshot.posits`, request the
sorted list explicitly with `check constraint "policy" with full manifest;`.
The digest uses the version 1 algorithm. Existing saved constraint definitions
and format 1.0 stores work with this release.

Start a script with `strict mutations;` to reject a write that uses a binding
promoted from several matching identities. Within one `add posit` command,
later additions can recall an earlier target or assertion by its canonical
Posit identity. The target, assertion, and meta-assertion can share one commit.

The regression tests cover both reported query shapes, compact audits,
and atomic writes across a store reopen. [Issue #6](https://github.com/Roenbaeck/positorium/issues/6) · [Verification and benchmarks](https://github.com/Roenbaeck/positorium/pull/7)
