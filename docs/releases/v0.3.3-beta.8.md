# Positorium 0.3.3-beta.8

This Rust release speeds up session-scoped searches and saved constraint
checks. To upgrade an application that uses an on-disk store, run

```sh
cargo add positorium@=0.3.3-beta.8 --no-default-features --features persistence
```

Traqula can start a join from a store-qualified identity in a conjunction
such as `where ?s = $s and ?c > 0%`. If an earlier comparison could raise a
data error, the planner preserves its evaluation order. For an appearance
such as `{(?i, item), ($s, session)}`, the planner counts candidates for
that session in sets containing the requested roles.

An assertion can take its source from an identity parameter. For example,
`and assert +a by $dev with 100% at $t` binds the canonical assertion
posit to `a`. Existing format 1.0 stores and saved constraints can be used
directly with this release.

On a persistent fixture with 999,710 posits, the identity query with the
certainty filter went from 285 ms on beta.7 to 0.22 ms. The query with the
session parameter in an appearance went from 221 ms to 0.19 ms. On the
100,070-posit fixture, the saved audit returned the same 26 findings and
went from 8.44 s to 0.74 ms. These are release-build medians from the same
stores for both versions. [Reported queries](https://github.com/Roenbaeck/positorium/issues/8)
