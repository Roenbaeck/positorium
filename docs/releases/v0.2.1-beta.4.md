# Positorium 0.2.1-beta.4

Concurrent clients can now read the same store while a writer is active and
prepare independent batches of evidence in parallel. One process owns the
store and one writer orders durable commits.

## Traqula concurrency

- A script containing only searches and explanations reads one consistent
  snapshot from start to finish, including when streaming results. A reader
  that starts after a writer exits sees its completed commands.
- A standalone `search … or add posit …` can return an existing identity from
  its snapshot. On a miss, it acquires the writer lock and repeats the search
  if the view changed. When the fallback supplies the missing key, concurrent
  callers create it once.
- Scripts made up of `add role` and `add posit` prepare bindings, candidate
  posits, and assertions concurrently. During commit the writer resolves
  canonical identities against the current store. Assertions keep the correct
  target when several additions name the same proposition.
- Scripts that mix queries and mutations hold the writer lock throughout and
  see their own earlier writes. Each mutation command commits atomically.
  Earlier successful commands survive a later failure.

Each in-flight append script holds its expanded candidates in memory until
commit. The language reference describes visibility, retries, and streaming.
[Traqula script visibility](https://github.com/Roenbaeck/positorium/blob/v0.2.1-beta.4/docs/reference/TRAQULA.md#script-visibility)

## Compatibility and upgrade

The patch works with existing format 1.0 stores and Traqula 1 scripts. It
uses the same HTTP, SSE, Python, WASM, Terrain, and query-plan contract
versions as beta.3. [Contract versions](https://github.com/Roenbaeck/positorium/blob/v0.2.1-beta.4/docs/reference/CONTRACTS.md)

Install the Python prerelease with

```sh
python -m pip install --upgrade 'positorium==0.2.1b4'
```
