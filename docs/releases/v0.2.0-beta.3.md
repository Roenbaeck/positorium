# Positorium 0.2.0-beta.3

This release introduces a planned, incremental Traqula executor with explicit
work and workspace limits. It also fixes query correctness issues, shares
temporal reduction across snapshots and effective evidence, and exposes the
chosen execution plan through `EXPLAIN`.

## Query correctness

- Ordinary snapshots reduce history before applying external Posit, value, and
  time bindings, so results are independent of join order. `latest` retains its
  separate filter-first meaning.
- Thing unions remain exact unless an ellipsis opens the appearance set.
  Negation locals, common typed union schemas, cutoff dependencies, limits, and
  sort domains are validated consistently, including empty-data cases.
- Invalid `search ... or add` commands fail before output or fallback mutation.
  Numeric/certainty sort mixtures remain errors, including values discarded by
  a top-k heap.

## Execution and performance

- Typed physical plans represent scans, joins, anti-joins, temporal reductions,
  projection, distinctness, ordering, and limits. `explain search ...;` and the
  Rust explanation API inspect the chosen plan without executing its query or
  fallback. Plan version 2 reports incremental eligibility and validation barriers.
- Shared interval-aware temporal reduction preserves equal and incomparable
  maxima and source-local multiplicity. Its dominance kernel uses at most
  `2(n - groups)` temporal comparisons, including witness selection.
- Eligible queries use lazy scans, indexed nested-loop joins, early safe
  filters, short-circuit absence checks, and incremental projection/distinctness.
  Unsorted limits stop after one lookahead row. Stable top-k ordering retains
  at most `limit + 1` projected rows with prepared exact numeric sort keys.
- Explicit query limits cap cumulative logical work across a script and live
  accounted workspace. They cover intermediate bindings, candidate postings,
  temporal scratch, distinct state, sorting, fallback identities, and cached
  effective cuts. Exhaustion aborts the script before fallback or later mutations.
- Rust, Python, WASM, and HTTP/SSE expose the controls. HTTP defaults to
  20,000,000 work units and 256 MiB of accounted workspace; requests may lower
  those caps. Other execution APIs default to unlimited query budgets.
- Regression tests cover budget boundaries and reuse, partial streams,
  comparison failures, temporal semantics, fallback safety, and interface framing.
  Windows documentation tests now accept CRLF line endings.
- The shared temporal and incremental benchmarks record 45 and 33 before/after
  cases; another 33 cases measure enabled budget accounting. On the measured
  M1 Pro host, a 256-by-256 Cartesian join with `limit 10` fell from about
  63.9 ms under materialization to about 21 microseconds incrementally.
  Accounting adds roughly 4–16% on most largest-scale incremental cases and
  about 35% on the materialized comparison control. These are fixture-specific
  measurements, not general performance guarantees. See the
  [methodology and complete results](https://github.com/Roenbaeck/positorium/blob/v0.2.0-beta.3/docs/development/BENCHMARKS.md).
- Updated social-preview artwork ships with the browser testbed.
- Native release archives build without the optional Python binding, avoiding
  a dependency on the build machine's Python installation. Python wheels retain
  their separate stable-ABI builds.

## Compatibility and upgrade

The Rust crate API advances to `0.2`. Explicit `ExecutionOptions` struct
initializers must include `query_limits` or use `..ExecutionOptions::default()`.
Query plan consumers must understand plan version 2, including its `top_k` and
`consume` operators and incremental execution fields.

Store format 1.0, Traqula 1, HTTP v1, SSE 1, WASM 1, Python 1, Terrain 1,
logical export 1, and identity remap 1 keep their versions. Existing stores
require no migration. The Python distribution version is `0.2.0b3`:

```sh
python -m pip install --upgrade 'positorium==0.2.0b3'
```

Correctness fixes can reject previously accepted invalid scopes, limits,
dependencies, and mixed sort domains. Eligible limited queries now stop early;
fallible comparisons, effective evidence, and identity-promoting fallback
queries retain complete validation. HTTP workloads exceeding the new default
query caps fail explicitly instead of continuing without those limits.

## Boundaries

Workspace accounting is not a process-RSS limit. Shared database storage,
parsing/planning, mutation staging, and collected output buffers are excluded;
combine query budgets with row limits or streaming. Earlier successful mutation
commands remain committed when a later search fails, and a failed stream may
already have delivered a partial result.

Temporal histories, full scans, and distinct state can still require substantial
workspace. Hash joins, compact bindings, effective-slice indexing/eviction, and
operator runtime metrics including `EXPLAIN ANALYZE` remain on the
[roadmap](https://github.com/Roenbaeck/positorium/blob/v0.2.0-beta.3/docs/development/ROADMAP.md).
